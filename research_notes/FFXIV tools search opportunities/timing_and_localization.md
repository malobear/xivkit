## A2. Recurring seasonal events and the gap for an evergreen "what's live now" page

### Takeaway
Seasonal events follow a very regular yearly calendar, so their spikes are predictable. Many sites already publish per-event walkthroughs within days (ConsoleGamesWiki, Sportskeeda, Eorzea Tavern, GameStrider, EpicCarry), and senseos.gg already runs a "when each event usually starts" page. Two things look open: a durable, icon-rich **"what's live now + rewards checklist"** page, and above all one in JA/DE/FR.

Show item icons per CLAUDE.md, a "missed past rewards available at the Gold Saucer / Mog Station" note, and a countdown. This fits XIVKit's checklist and tool style, and links and authority build on one URL instead of a new page every year.

**XIVKit's own localization (repo check, 2026-11-11)**
- Translations are client-side only. i18n.js picks the language from `?lang=` query string, then localStorage, then navigator, and rewrites text in the browser. The pages carry **no hreflang** tags, sitemap.xml contains **no `?lang=` URLs**, and index.html's canonical is `https://xivkit.com/` (no lang). get-ready-for-evercold.html has no canonical and zero `data-i18n` attributes, so it is English-only. Other guides have only 3 to 8 `data-i18n` attributes (retainer-ventures 3, trade-in-mounts 4, jump-puzzle-macros 6, inventory-decluttering 6), so their body copy is English. — repo files `i18n.js`, `sitemap.xml`, `index.html`, `*.html`; README "Translations" section
- Google advises using separate URLs per language version with hreflang annotations, rather than switching content by cookies or browser settings. — [Google Search Central: Managing multi-regional and multilingual sites](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)

### Inferences
- **XIVKit's JA/DE/FR translations are effectively invisible to search today.** Googlebot crawls without a `lang` param, and the canonical points every variant at English. Before any non-English content strategy can pay off, the site needs indexable per-language URLs (e.g. `/ja/…` or at least crawlable `?lang=ja` URLs with self-referencing canonicals), hreflang clusters, and sitemap entries. This is the single highest-leverage localization finding.
- German and French are the clearest openings. The established DE/FR sites stopped maintaining comprehensive FFXIV lists years ago, and the space is filling with machine translations. A data-driven page with official German and French item names (not translations of English names) would stand out.
- Japanese is harder: game8 has a dedicated FF14 database with many list pages, and the official Eorzea Database exists in Japanese. JA effort is best spent on tools rather than prose guides.

### Gaps
- Gamewith, ff14.nemui and other JP blogs did not surface in these searches. I didn't verify whether Gamewith still maintains FF14 pages.
- No German or French community wikis (e.g. ffxiv.de-type wikis) surfaced. They may exist, but they didn't appear for these queries.
- Real Google rankings by locale (google.de, .fr, .co.jp) can't be checked with this US-only search tool, so all ranking observations are approximate.

## B2. Which content types travel well across languages

### Takeaway
Data-driven tools whose item, mount and quest names come straight from the game's own localized data translate almost for free and avoid the main weakness of competitors (machine-translated names). Opinion and strategy guides ("worth the tomes?", gil advice) need native writing or careful review.

### Cited Findings
- The official Lodestone and Eorzea Database run in all four client languages (na/eu/fr/de/jp.finalfantasyxiv.com). The All Saints' Wake special page, for example, exists on NA and EU Lodestone with region-local times. — [Lodestone NA](https://na.finalfantasyxiv.com/lodestone/special/2026/All_Saints_Wake/tfrx2rkv52); [Lodestone EU](https://eu.finalfantasyxiv.com/lodestone/special/2026/All_Saints_Wake/tfrx2rkv52)
- Competing non-English pages are often machine-translated English: games.gg serves the same 7.55 article in DE, NL, UR and HI, conquestcapped and mmogah run /de/ and /fr/ copies, and jeu.video publishes the same 7.57 story in IT, PT-BR, EN and FR. — [games.gg DE](https://games.gg/de/news/final-fantasy-14-patch-755-abschluss-von-dawntrail-mit-relics-und-hildibrand/); [mmogah DE](https://www.mmogah.com/de/news/ffxiv/2026-efficient-gil-making-methods-in-ffxiv-no-crafting-required); [jeu.video](https://jeu.video/article/ffxiv-patch-757-matchmaking-japon)

### Inferences
- **Travel well (low per-language cost):** item, mount and reward checklists with icons (event rewards, trade-in mounts, Hunt for Astronomy rewards), market-price calculators (retainer ventures, trade-in mats), the MSQ tracker (quest names from game data), jump puzzle macros (numbers), and Fan Fest bingo (short strings). XIVAPI sheets can be queried with a language parameter (ja/de/fr) to get official in-game names. This should be checked against the XIVAPI v2 docs before building on it. The README says item names currently stay English in every language, which forfeits exactly this advantage for item-name queries like "Reittier X bekommen".
- **Need native writing or review:** opinion and value judgments ("Grind or Buy the Mats?", "Worth the Tomes?"), the Evercold prep checklist (system names like Evolved mode, Bastion and Zephyr have official localized names that need checking on the JP/DE/FR Lodestone), and gil-making advice. CLAUDE.md already asks to flag terminology such as Housing, Glamour and Retainer.
- Japanese query phrasing is formulaic ("〇〇 入手方法", "〇〇 一覧", "金策"). Titles and H1s in JA should follow those patterns rather than literal translations of the English titles.

### Gaps
- I didn't fetch XIVAPI docs to confirm the exact `language` parameter syntax on beta.xivapi.com.
- I didn't find the official localized names for Evercold, Bastion, Zephyr and Evolved mode in JA, DE and FR. The JP, DE and FR Lodestone pages need checking.
